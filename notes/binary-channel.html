Capacity and reliability are different questions

4 min read · Companion to a runnable educational example

A binary symmetric channel flips each transmitted bit independently with probability p. Two natural questions concern this channel: how much information can be transmitted reliably, and how often does a particular code make a mistake?

The information limit

h₂(p) = −p log₂p − (1 − p) log₂(1 − p)
C = 1 − h₂(p)

Capacity is measured in bits per channel use. It describes an asymptotic achievable information rate with suitable coding over increasingly long blocks. At p = 0.1, capacity is about 0.531 bits per channel use. At p = 0.5, each output is independent of the input, and capacity is zero.

A concrete code

Transmit each bit three times and use a majority vote. Its information rate is 1/3. Decoding fails if at least two of the three channel uses flip.

Pr(decoding error) = 3p²(1 − p) + p³ = 3p² − 2p³

This expression relies on independent flips. Correlated noise would require a different calculation.

What the experiment shows

At each of 21 noise settings, the demo generates 100,000 independent three-bit noise patterns. The observed decoding error is compared with the analytical expression. A separate panel plots channel capacity.

The capacity curve is an information limit. The repetition curve measures a particular decoder at a specified rate. The example does not claim that this repetition code reaches capacity.
